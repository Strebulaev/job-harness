# MVP plan — Telegram bot that finds jobs and delivers documents

Goal (decision `docs/decisions/0014-mvp-is-single-user-telegram-pipeline.md`): the Principal opens Telegram, fills in a profile, connects OpenRouter and SuperJob, adds an RSS feed, starts the search, and from then on receives in chat, per suitable job: the job link, a tailored resume PDF and a cover letter. The Principal fills in the profile and nothing else.

This plan is not a decision, fact, guardrail or procedure. It has no `track` and no `expires`. Its only status is the per-step marker. It replaces the earlier M4–M6 MVP plan (decision 0013, superseded): compose, render and gates are kept; email sending, inbox tracking and follow-ups are deferred (section 7).

## Read this first (cold session)

- **Project:** local-first contractor job-search harness, single user. Spec: `spec.md` (section numbers below refer to it). Decisions: `docs/decisions/` (full text of D1–D9 in the frozen `docs/DECISIONS.md`). Facts: `docs/facts/`. Guardrails: `docs/guardrails/`. Adapter notes: `docs/SOURCES.md`. Prompts: `docs/PROMPTS.md`.
- **Stack:** Python 3.12, `uv`, pydantic v2, SQLAlchemy 2 + Alembic (SQLite WAL), Typer CLI `jh` in `src/jobharness/cli.py`, httpx, apscheduler (already a dependency), pytest, ruff, `mypy --strict`. Run everything through `uv run`. `uv` and Python 3.12 were NOT installed on the dev machine when this plan was written; install `uv` first (`uv sync` fetches Python 3.12).
- **Already built (M1–M3, plus step 1.1):** config/settings (`src/jobharness/settings.py`, unknown keys are errors, `Settings.from_yaml`), schemas (`schemas/profile.py` with `validate_profile` and `lint_profile`, `jd.py`, `archetype.py`, `positioning.py`, `documents.py`), DB models and Alembic migration `0001_initial_schema.py` (tables `sources`, `jobs`, `documents`, `applications`, `contacts`, `messages`, `events`, `followups`, `contracts`, `eval_runs`, `llm_calls`), state machines (`db/state_machine.py`), LLM layer (`llm/`: `provider.py`, `anthropic_provider.py`, `fake_provider.py`, `structured.py`, `prompts.py`, `prompt_versions.py`, prompt files `llm/prompts/<name>/v1.md`), ingest adapters (`ingest/manual.py`, `rss.py`, `email_alerts.py`, dedup), parser (`parse/`), router (`route/`), fact retrieval (`compose/retrieval.py`, step 1.1, written but never run: run its tests first). CLI commands that exist: `init`, `doctor`, `profile validate|lint|show`, `parse run`, `job add`, `ingest run`, `route run`, `eval run` (router suite only).
- **Not built yet (stub packages or absent):** `compose/` beyond retrieval, `render/`, `eval/`, `send/`, `track/`, `capacity/`, `report/`, any `bot/`, `secrets/`, `pipeline/`. `tests/e2e/` has only `.gitkeep`.
- **Test fixtures for LLM calls:** `FakeProvider` returns outputs keyed by request hash from `tests/fixtures/llm/`. `scripts/gen_parse_fixtures.py` shows how fixtures are generated; follow the same pattern for new prompts.
- **Hard rules:**
  - Automated tests and acceptance commands run offline: `FakeProvider`, mocked HTTP (`httpx.MockTransport`) and a fake Telegram messenger. Live calls with real keys happen only in the human smoke test, step 6.3 (guardrail `docs/guardrails/mvp-gates-offline-only.md`).
  - Provider keys: delete the chat message first, store only encrypted, never log or echo (guardrail `docs/guardrails/provider-keys-never-persisted-in-clear.md`, fact 0014: Telegram bot chats are not end-to-end encrypted).
  - Generated resume and cover content must be derivable from the profile; never invent employers, titles, dates, metrics or technologies (spec §2.1). Fixtures use `config/profile.example.yaml` (Acme/Globex).
  - The bot answers only the owner's Telegram user id (decision 0014). Nothing is ever sent to an employer in the MVP.
  - PDFs are rendered with the `typst` binary on PATH (decision 0012); Typst is installed in CI only, so render-dependent tests skip locally without it.
  - Ingest only sources whose terms allow programmatic access (spec §2.4, `docs/SOURCES.md`).
- **After every step:** `uv run ruff check src/ tests/ && uv run mypy && uv run pytest tests/unit tests/integration -q` must stay green. Update the step marker below in place, with the date and a one-line summary.
- **Markers:** `[ ]` pending, `[~]` in progress, `[x]` done, `[!]` blocked, `[>]` moved. `‖` after a marker means the step can run in parallel with other ready steps.

## Open decisions (defaults chosen; override before the named step)

- **Telegram library:** `aiogram` 3 (async, fits the project). Override before step 4.1.
- **Bot runtime:** long polling in one process (`jh bot run`), no webhook, so no public URL is needed. Hosting is any always-on machine; step 6.2 packages it with Docker.
- **Document language:** English resume and cover letter regardless of the posting language. Override before step 1.2.
- **Gate failure:** a job whose documents fail the gates after the regeneration loop is not delivered; `/status` shows the count. Override before step 5.2.
- **Search interval and caps:** every 60 minutes, at most 20 new jobs processed per cycle and 10 deliveries per day, all settable in `bot` settings. Override before step 5.1.
- **Model ids:** chosen by the Principal in `/models` from OpenRouter's model list; no ids are pinned in the repo (decision 0015).
